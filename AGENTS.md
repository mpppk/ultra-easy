# Using Vite+, the Unified Toolchain for the Web

This project is using Vite+, a unified toolchain built on top of Vite, Rolldown, Vitest, tsdown, Oxlint, Oxfmt, and Vite Task. Vite+ wraps runtime management, package management, and frontend tooling in a single global CLI called `vp`. Vite+ is distinct from Vite, and it invokes Vite through `vp dev` and `vp build`. Run `vp help` to print a list of commands and `vp <command> --help` for information about a specific command.

Docs are local at `node_modules/vite-plus/docs` or online at https://viteplus.dev/guide/.

## Built-in Commands vs Scripts

`vp <name>` runs a built-in command. `vp run <name>` runs a `package.json` script or a `vite.config.ts` task. Scripts cannot overwrite built-ins, so `vp dev` and `vp run dev` may do different things. Check `package.json` and `vite.config.ts` first, and run `vp run <name>` when the project defines a script or task with that name.

## Review Checklist

- [ ] Run `vp install` after pulling remote changes and before getting started.
- [ ] Run `vp check` and `vp test` to format, lint, type check and test changes.
- [ ] Check if there are `vite.config.ts` tasks or `package.json` scripts necessary for validation, run via `vp run <script>`.
- [ ] If setup, runtime, or package-manager behavior looks wrong, run `vp env doctor` and include its output when asking for help.

# ultra-easy

Cloudflare Workers + TanStack Start (React) project. Package manager is **bun** (not npm). `packageManager` is `bun@1.4.0`.

## Workspace Layout

bun workspace (`workspaces: ["packages/*"]`). The repository root is itself the app (`src/`), and shared libraries live under `packages/`.

- `packages/approval-core` (`@app/approval-core`) — approval workflow domain core. Import by package name (`@app/approval-core`, `@app/approval-core/testing`), never by relative path into `packages/`.
- `defaultPackage: "."` in `vite.config.ts` keeps bare `vp dev` / `vp build` / `vp preview` pointed at the root app instead of prompting for a package. vp reads it **statically**, so the config must stay `export default defineConfig({ ... })` — assigning to a variable and doing `export default config` makes vp ignore it.
- Target a package with `vp -C packages/approval-core <command>`; run a script everywhere with `vp run -r <script>`.

## Commands

- Use `bun` for package operations (`bun install`, `bun add`, `bun run <script>`).
- Use `vp` built-ins for dev/validate: `vp dev`, `vp build`, `vp preview`, `vp check`, `vp test`.
- `vp run <script>` runs `package.json` scripts; `vp dev` / `vp test` run the built-ins.
- Validate with `vp check` and `vp test`; build with `vp build`; deploy with `bun run deploy` (`vite build` + `wrangler deploy`).

## Notes

- `vite.config.ts` applies `@cloudflare/vite-plugin` (ssr environment) + TanStack Start + React. The Cloudflare plugin is skipped when `VITEST=true` because it is incompatible with Vitest (`resolve.external` in ssr env).
- Wrangler config is `wrangler.jsonc` (worker name `ultra-easy`, `nodejs_compat`, observability enabled).
- CI (`.github/workflows/check.yml`) runs `vp install`, `vp check`, `vp test` with bun.
- Secrets live in the 1Password Environment named `ultra-easy` (`GYAZO_API_TOKEN`, `CLOUDFLARE_API_TOKEN`). Do not commit plaintext secrets.
- `src/routeTree.gen.ts` is regenerated by TanStack Router during `vp dev` / `vp test` with its own formatting (single quotes, no semicolons), which then fails `vp check`. The committed version is oxfmt-formatted; restore it with `git checkout -- src/routeTree.gen.ts` before running `vp check` locally.
- Project skills are installed at project scope in `.agents/skills` (mpppk/skills, helpfeel/cosense-cli, mattpocock/skills grilling + domain-modeling).
